FEATURED PROJECT

1919 경성역

First-Person Horror Stealth Puzzle Game

일제강점기 경성역을 배경으로, 순사를 피해 단서를 찾고 퍼즐을 푸는 1인칭 공포·잠입 게임입니다. 어두운 경성역 분위기, 순사의 추격과 감시, 제한된 시야와 손전등, 잠긴 문과 단서 탐색, 사운드와 점프스케어를 통해 긴장감을 전달합니다.

구현 상세

Project Goal

일제강점기 경성역이라는 역사적 공간을 공포·잠입 게임의 무대로 구성하고, 플레이어가 직접 단서를 찾고 문을 열고 퍼즐을 해결하면서 독립운동 문서를 회수하는 경험을 목표로 했습니다.

My Role

플레이어 이동, 달리기, 스태미나, 웅크리기, 상호작용, 인벤토리, 문/잠금장치, 아이템 배치 퍼즐 등 게임의 진행 흐름에 직접 연결되는 게임플레이 시스템을 담당했습니다.

Development Focus

기능을 따로 만드는 것보다, 플레이어가 아이템을 획득하고 인벤토리에서 확인한 뒤 문이나 퍼즐 오브젝트에 사용하는 흐름이 자연스럽게 이어지도록 구성하는 데 집중했습니다.

Result / Plan

엔딩까지 플레이 가능한 프로토타입을 제작했고, 교내 게임경진대회 최우수상 1등을 수상했습니다. 이후 퍼즐 스케일, 미니맵, 사운드, 환경 메시·라이트, 순사 AI를 개선할 계획입니다.

인벤토리 시스템

목표 아이템 획득, 목록 표시, 사용, 버리기 기능 구현

결과 단서와 아이템을 UI로 확인하고 선택 가능

구현 구조

아이템을 획득하면 구조체 기반 데이터가 배열에 저장되고, 인벤토리 UI를 열 때 해당 데이터를 슬롯 위젯에 바인딩해 표시하는 방식으로 구성했습니다.

주요 노드 / 구조

ST_ItemData Struct, Array, Create Widget, Add to Viewport, Set Input Mode Game and UI, Set Show Mouse Cursor, For Each Loop, Set Brush From Texture, Set Text를 활용해 데이터 저장과 UI 갱신 흐름을 연결했습니다.

개발 포인트

단순 보관 UI가 아니라 문·퍼즐 시스템과 연결되는 구조가 필요했기 때문에, 아이템 데이터에 KeyID, CanUse, CanDiscard, 태그 정보를 포함할 수 있도록 설계했습니다.

전체 인벤토리에서 일일이 찾는 구조보다 현재 대상 앞에서 필요한 키 아이템만 보여주도록 UX를 분리해, 퍼즐과 문 사용 흐름이 더 자연스럽게 이어지도록 만들었습니다.

문 / 잠금장치 시스템

목표 아이템·퍼즐 조건에 따라 문 상태 제어

결과 인벤토리와 퍼즐 조건이 연결된 진행 구조 구현

구현 구조

문은 단순 오브젝트가 아니라 잠김 / 열림 / 닫힘 상태를 분리해 관리했습니다. 아이템 사용이나 퍼즐 성공 여부에 따라 문 상태가 갱신되도록 만들었습니다.

주요 노드 / 구조

Boolean State(IsLocked, IsOpen), Timeline, Lerp, Set Relative Rotation, Branch, Play Sound 2D, Open / Unlock Function 구조를 사용해 잠금 해제와 문 열림을 분리했습니다.

개발 포인트

문은 진행 제어의 핵심 장치이기 때문에, 인벤토리에서 올바른 키를 사용했는지와 퍼즐 조건 충족 여부가 문 상태에 정확하게 반영되도록 처리하는 데 집중했습니다.

GIF Placeholder1919_altar_puzzle.gif

제단 / 아이템 배치·회수 퍼즐 시스템

목표 아이템 태그 조건을 검사해 배치·회수·문 활성화를 연결

결과 아이템을 단순 사용이 아닌 상호작용형 퍼즐 구조로 확장

구현 구조

아이템 데이터에 PlacementTag와 UseTag를 저장하고, 제단 또는 문/퍼즐 오브젝트의 요구 조건과 비교해 정답 여부를 판별하도록 구성했습니다. 아이템은 배치 후 다시 회수할 수 있으며, 상태 변화가 연결된 장치에 반영됩니다.

주요 노드 / 구조

PlacementTag, UseTag, RequiredPlacementTag, RequiredUseTag, Stored Item Reference, Branch, Set Actor Location / Visibility, Custom Event를 사용해 배치·회수·문 상태 갱신을 연결했습니다.

개발 포인트

정답 아이템을 한 번 쓰고 끝나는 구조보다, 플레이어가 직접 아이템을 배치하고 다시 회수하며 조건을 실험하는 퍼즐 경험을 만들고 싶었습니다. 회수 시 연결된 문 상태까지 다시 갱신되도록 처리한 점이 핵심입니다.

CREATIVE DIRECTION

귀삼

Game Concept / Planning Portfolio

`귀삼`은 조선 후기 한국형 공포 분위기와 설화적 소재를 바탕으로 기획한 1인칭 서바이벌 퍼즐 호러 콘셉트입니다. 개발 프로젝트는 아니지만, 제가 지향하는 스토리 중심 공포·모험 게임의 방향성과 세계관 구성 취향을 보여주는 기획 작업입니다.

Korean HorrorSurvival PuzzleStory-drivenFirst-personJoseon Fantasy

Concept

조선 후기 산골 고을과 대저택, 동굴을 배경으로 한 한국형 서바이벌 퍼즐 호러 콘셉트입니다. 한국 설화, 무속, 약초, 식물 변이 공포를 결합해 한국적인 공포 분위기를 만드는 것을 목표로 했습니다.

Gameplay Direction

1인칭 시점에서 제한된 자원으로 공간을 탐색하고, 문서와 단서를 통해 퍼즐을 해결하며, 위협적인 존재를 피해 다음 구역으로 나아가는 구조를 기획했습니다.

Portfolio Note

실제 개발 완료 프로젝트가 아닌 기획 포트폴리오이므로, 개발 결과물이 아니라 게임 콘셉트와 세계관, 장르 방향성을 보여주는 자료로 배치합니다.
